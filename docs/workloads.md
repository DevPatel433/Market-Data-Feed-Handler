# Workloads

Generated by `feed_gen_events` (`src/workload.cpp`). Every workload is a pure function of its parameters: **same seed + same parameters => byte-identical file**, on any compiler or build mode (checked by the smoke test, a cross-build comparison, and the CI `samples-reproducible` job). The PRNG is SplitMix64 rather than `<random>` because standard distributions are implementation-defined.

## Clean stream (shared by all profiles)

Per seed, one sequence of messages with `seq = 1..count`: ~45% Add, ~20% Cancel, ~25% Trade, ~10% Heartbeat. Cancels target live orders (cap 4,096). Prices are integer ticks around `10000 + 100 * instrument`. Faults use an *independent* RNG stream, so with faults disabled every profile yields the same bytes as `normal` (tested).

## Profiles

| Profile | What it does | Purpose | Ground truth (`manifest.json`) |
|---------|--------------|---------|-------------------------------|
| `normal`    | Constant-rate pacing | Baseline | none |
| `bursty`    | Same mean rate, but each group of `burst_size` messages is emitted at `burst_multiplier`x the mean rate, then idle until the next cycle | Queue occupancy, overload (Phase 5) | none; burst k starts exactly where `normal` would place message `k*burst_size` |
| `malformed` | Corrupts ~`fault_ppm` of frames: truncation, bad version, unknown type, lying `payload_len`, oversize | Decoder rejection (Phase 1) | `malformed` |
| `duplicate` | Re-sends ~`fault_ppm` of frames immediately | Sequencer duplicate detection | `duplicated` |
| `gap`       | Removes runs of 1-3 frames (never the first) | Gap detection, recovery | `dropped` |
| `reorder`   | Swaps adjacent frames (offsets keep their slots) | Out-of-order classification | `reordered` |

Default `fault_ppm` is 10,000 (1%). `frames_out` in the manifest is the number of frames in the file.

## Known caveats

- A *malformed* frame still occupies its sequence number in the generator's view, so a receiver will see both a rejection and (later) a gap for that number. This is intended and matches `metrics.md` §4.
- Every mutation the generator applies is rejected by the Phase 1 decoder, so for the `malformed` profile `rejected_total` equals the manifest's `malformed` exactly, and for every other profile it is 0 (asserted in `tests/test_decoder.cpp` and `tests/smoke_replay.sh`). A header-only peek cannot catch the `oversize` mutation; the full decoder does, via `too_large`/`length_mismatch`.
- `gap` can drop the final frames of a stream; a receiver cannot know until a later heartbeat or message arrives.
- Single stream only (`--stream-id`). Multi-stream workloads can be added when sequencing needs them.

## Fault injection on existing files

The generator profiles above each apply one fault type at generation time. `feed_fault_inject` instead
post-processes any replay file and can combine drops, duplicates and reordering with independent rates
(see `sequencing.md` §7). Use profiles for single-fault baselines and the injector for mixed or tunable faults.
